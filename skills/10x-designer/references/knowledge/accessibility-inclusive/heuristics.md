# Accessibility & Inclusive Design — Critique Heuristics

Deduplicated "if X then problem Y, fix Z" rules, synthesized from decades of established UX research and practice. WCAG success criteria cited where applicable.

---

## Color, contrast & perception

- **If** body-text contrast is below 4.5:1 (or 3:1 for large text ≥18pt/14pt bold) **then** low-vision and aging users can't read it **because** insufficient luminance difference causes fatigue/illegibility — **fix:** raise to WCAG AA (4.5:1 / 3:1); aim AAA (7:1 / 4.5:1) for critical text. Combine brightness contrast (black/white) AND hue contrast (complementary), and set colors in CSS so users can override. (WCAG 1.4.3/1.4.6)
- **If** pure black sits on pure white **then** dyslexic users and many others get glare/blur **because** maximum contrast can worsen readability — **fix:** off-black on off-white (e.g. #111 on #eee).
- **If** meaning is conveyed only by color (red/green status, colored links, map/graph series, color-coded sections) **then** ~5% color-blind, low-vision, grayscale, and print users lose it **because** red/green or blue/yellow collapse — **fix:** add a second cue (text label, icon shape, position, line/fill style); supply a key; use color-blind-safe palettes (ColorBrewer); check in grayscale. (WCAG 1.4.1)
- **If** links are distinguished by color only (no underline/border/button) **then** color-blind/low-vision users can't find them **because** color isn't universally perceivable — **fix:** underline or add a non-color cue.
- **If** an audio/sound cue (chat reply, game event) has no visual equivalent **then** deaf users miss events — **fix:** add a "visual bell" (tab color change, flashing mute button, brief background flash).

## Images, media & non-text

- **If** an image lacks `alt`, the alt is a filename, decorative images get descriptive alt, or alt merely duplicates the caption **then** screen-reader users get noise or nothing **because** AT can't distinguish meaningful from decorative — **fix:** purposeful/functional alt for meaningful images ("Go to next page"); null `alt=""` for decorative/spacer/repeated-logo images; for image links describe the destination; caption should add to, not repeat, alt. (WCAG 1.1.1)
- **If** a chart/graph's alt lists every data point or omits title/axes **then** it's useless **because** users can't get the gist — **fix:** state title, what's charted (Y against X), and overall trend without drawing conclusions; verify with a tester.
- **If** video/audio lacks captions, transcript, or description **then** deaf/HoH and blind users can't access it **because** media carries no machine-readable text — **fix:** synchronized captions (speech + meaningful sounds/tone, mixed-case, banded below the action so they don't obscure it), a transcript, and audio description of key visuals; user-controlled keyboard-accessible playback, no autoplay. (WCAG 1.2.x)
- **If** text is rendered as a graphic (graphic text, image menus, address-as-image) **then** it can't be resized, restyled, recolored, machine-read, or SEO-indexed **because** images aren't flexible — **fix:** use real selectable text styled with CSS (web fonts for styled nav). (WCAG 1.4.5)
- **If** content lives only in Flash, scanned-image PDFs, or text-as-image **then** blind, low-vision, dyslexic, and locked-down/old-AT users are excluded — **fix:** provide real text + an accessible HTML equivalent (the pizza-shop case: Flash intro + scanned-PDF menu + address-image excluded up to ~10% of traffic).

## Keyboard, focus & motion

- **If** an interactive element can't be reached/activated by keyboard (Tab to select, Enter/Space to activate), or focus is trapped, or it's mouseover/hover-only **then** keyboard, switch, voice, and screen-reader users are blocked **because** point-and-click assumes a mouse — **fix:** make every control keyboard-operable in logical order with an exit path. (WCAG 2.1.1/2.1.2)
- **If** the focus indicator is removed (`outline:none` / `:focus{outline:0}`) **then** keyboard users can't tell where they are **because** the browser default was suppressed — **fix:** never zero out outline; provide a strong visible focus style (mirror the hover cue). (WCAG 2.4.7)
- **If** tab order doesn't follow the visual/logical sequence (submit not last) **then** keyboard users get lost and may submit before completing fields **because** tab order follows source order — **fix:** order elements logically in code; put submit last.
- **If** content auto-plays, auto-advances (carousel), flashes, or scrolls without user control **then** it distracts, harms low-attention/cognitive users, and flashing can trigger seizures — **fix:** never autoplay; provide pause/stop/hide; never flash >3×/second; animations static-until-interaction. (WCAG 2.2.2/2.3.1/1.4.2)
- **If** a pop-up is easy to trigger (mouseover) but hard to dismiss (tiny X, no keyboard close) **then** motor-disabled users get stuck — **fix:** allow ESC-to-close (spelled out), close target ≥13×13px, keyboard reachable.
- **If** touch/click targets are tiny or tightly packed **then** users with tremor, arthritis, or fat fingers mis-tap — **fix:** enlarge and space targets (voting-machine guidance ≥0.5in × 0.7in, ≥0.1in apart; ~13×13px minimum); wrap icons in adjacent text links; use tolerant/sticky drop-downs.

## Structure, navigation & layout

- **If** heading levels are skipped, out of order, or used for visual styling/decoration only **then** screen-reader navigation breaks **because** 61% of screen-reader users scan headings first — **fix:** correctly nested, descriptive headings (h1→h2→h3) that reflect the real outline, only for real sections.
- **If** there's no "skip to content"/skip-navigation link or HTML5/ARIA landmarks **then** screen-reader and keyboard users wade through repeated nav on every page **because** there's no bypass — **fix:** add a skip link (off-screen via `text-indent:-5000px`, not display:none/visibility:hidden, which AT skips) and landmark roles (`main`, `nav`, `banner`, `search`). (WCAG 2.4.1)
- **If** the page opens with nav/decoration and the most important content isn't first in the DOM **then** linear AT/keyboard users hit clutter before content — **fix:** put main content first (inverted pyramid), heading-first.
- **If** layout uses fixed pixel widths/text sizes and breaks when text is zoomed to 200% **then** low-vision users get horizontal scroll, clipping, or hidden nav **because** rigid units don't reflow — **fix:** relative units (em/%), flexible/responsive grids; the whole site (layout, images, embeds, nav) must "grow gracefully"; support resize to 200% without loss. (WCAG 1.4.4)
- **If** tables are used for page layout **then** screen readers linearize illogically and can't tell layout from data tables — **fix:** use CSS for layout; keep any unavoidable layout table simple (TR/TD only) with linear source order.
- **If** a data table lacks header associations (`scope`/TH), CAPTION, or SUMMARY **then** non-visual users lose row/column context — **fix:** tie headers to data with `scope="col"/"row"`, add CAPTION + SUMMARY, and a skip-table link.
- **If** structure/grouping is conveyed only by CSS **then** styles-off and screen-reader users miss relationships — **fix:** encode grouping with structural tags; the unstyled source must read logically.
- **If** content sits behind untitled frames or the same function is named/placed inconsistently across pages **then** wayfinding and mental models break — **fix:** avoid frames (title + NOFRAMES if used); keep navigation consistent and label equivalent components identically. (WCAG 3.2.3/3.2.4)

## Forms, errors & time limits

- **If** form fields lack a programmatically associated `<label for>` (placeholder-only, default text) **then** screen-reader users don't know what to enter **because** placeholders vanish on focus and aren't labels — **fix:** real `<label>` before the field; group related fields with FIELDSET/LEGEND; ensure submit graphic text matches its `value`. (WCAG 3.3.2/4.1.2)
- **If** error messages appear at page top / in a modal that closes / only as a red field **then** users (and AT, and color-blind) miss them **because** the change is upstream of the cursor or carries no announced meaning — **fix:** inline error next to the field, downstream of the cursor, with `role="alert"`, explicit text saying which field and why, and a correction suggestion. (WCAG 3.3.1/3.3.3)
- **If** a CAPTCHA is image-only **then** blind users are locked out **because** the letters can't be in alt — **fix:** add an audio CAPTCHA, logic question, honeypot, or alternative submission path.
- **If** a field is collected just because "everyone asks" / "might be nice," or one field is a hidden proxy for another (salutation→gender) **then** it adds friction, erodes trust, and produces offensive failures (Cambridge pediatrician gym lockout) — **fix:** run a structured question protocol ("why do we ask this?"); remove or make optional; never collect proxy fields.
- **If** identity fields use a closed binary list (gender) or reject "non-standard" real names/formats/hyphens/diacritics **then** users who don't fit are excluded and stressed (Native, trans, non-Western identities) — **fix:** offer Custom + free text or omit the field; accept the broadest range; never tell a user their name "isn't real" or "violates" policy.
- **If** required fields force users to invent/falsify data they don't have **then** they feel uncomfortable and the data is unreliable — **fix:** make such fields optional ("everyone has different limits").
- **If** a task is timed tightly with no warning or save **then** slower, AD/HD, and motor-disabled users get timed out and lose work — **fix:** be generous (if 5 min suffices allow ~15), warn before timeout, allow extend/turn-off, auto-save/retain entered data. (WCAG 2.2.1)

## Content, language & cognition

- **If** link text is "click here," "read more," or non-descriptive/repeated **then** users scanning a link list (by sight or ear) can't tell where links go — **fix:** make link text describe the destination, keyword-first; link the headline, not "read more." (WCAG 2.4.4)
- **If** the page is a "wall of words" with long paragraphs/sentences and no headings/lists **then** low-literacy, ESL, cognitive, dyslexic, AD/HD, and rushed users can't scan **because** there's no structure for F-pattern scanning — **fix:** short sentences (~10–15 words), short paragraphs, useful headings, bulleted lists, keywords first; highlight key info.
- **If** instructions reference an element by color/location only ("click the green button on the right") **then** non-visual users can't follow — **fix:** reference the element by its text label (color/location only as an add-on). (WCAG 1.3.3)
- **If** body text is justified, all-caps, serif, cramped, or over a background image **then** readability and tracking suffer (the dyslexic "river effect," letter confusion) — **fix:** real text, left-align (ragged right), mixed case, sans-serif with large x-height, line-height ≥1.5, never text over images. (WCAG 1.4.5/1.4.8)
- **If** copy is written at the author's reading level **then** ESL and many native readers can't parse it **because** creators overestimate audience reading ability (avg US adult ≈ 9th grade) — **fix:** run Flesch-Kincaid, build a reading-level content map, edit down to target.
- **If** a long page gives no length cue, contents list, or onboarding **then** ESL users get disoriented and bail — **fix:** read-time labels, anchor-linked Contents lists, onboarding with progress bars, tooltips for unfamiliar terms, a working print stylesheet.

## Compassion & stress cases

- **If** copy/imagery defaults to celebratory tone ("Here's your year!", confetti) **then** it's jarring or cruel for users in grief/crisis **because** it assumes a positive emotional state (Facebook Year in Review showed a dead child, a funeral urn) — **fix:** neutral, abstract framing that "leaves room to be wrong."
- **If** error/rejection copy uses accusatory words ("violates," "not approved," "not real") or jokes **then** users feel attacked in a touchy moment — **fix:** remove blame/humor; clarify policy, give clear next steps; lean on visual design (not copy) for playfulness.
- **If** a destructive, public, or financial action lacks a statement of consequences/reversibility **then** users hesitate, abandon, or are harmed — **fix:** add a short clear note before the action (Simple's "This is a reversible process" raised willingness and cut fraud).
- **If** an action makes private info public or notifies others without explicit warning **then** it can out or endanger users (UT Queer Chorus outing) — **fix:** warn before publishing; ask whether to make visible.
- **If** a feature/onboarding forces users into a few preset "journeys" or assumes their goal **then** it alienates anyone outside the mold (queer, single, infertile, short-cycle) — **fix:** ask users what they want to track/do; accept nuance.
- **If** an automated/ML feature (autotagging, recommendations) ships without QA on sensitive subject matter **then** it produces hurtful/racist/atrocity-mischaracterizing output **because** patterns fail badly out of context — **fix:** deliberately test on tragedy/disaster/identity imagery; prefer recommend-and-confirm or opt-in over auto-apply; don't offload cleanup onto users.
- **If** a streak/goal mechanic resets to zero on a single missed day **then** chronic-condition and long-term users feel punished and churn — **fix:** reward sustained, restartable progress ("tomorrow I can try again").
- **If** an org has no path/content for the in-crisis context (emergency, deletion-in-a-hurry) **then** the most urgent users are abandoned — **fix:** journey-map a crisis persona; ensure crisis content exists and is findable.
- **If** an element is tuned only for the common context (cheery elevator voices) **then** it can be hostile in another (midnight, only people in crisis) — **fix:** map personas × contexts; allow context-appropriate suppression.

## Cross-cultural & global

- **If** a typeface is chosen because it "looks like" a culture (Neuland="African," wonton/chop-suey="Asian," "Mandarin Regular") **then** it is stereotypography carrying racist connotations — **fix:** drop it; use type designed by people from the target culture and credit them.
- **If** meaningful icons appear without text labels **then** comprehension drops sharply across cultures **because** icons are abstract and culturally interpreted (icon+text beats icon-alone) — **fix:** pair every meaningful icon with descriptive text; keep icon sets consistent, high-contrast, single-meaning, customizable.
- **If** UI containers/microcopy have fixed widths sized to English **then** translations overflow/truncate **because** strings commonly run 1.5–2× longer (German ~30%; "Follow"→katakana ~20% wider) — **fix:** leave space, allow wrapping, keep components expandable; use expansion-factor tables; move labels to positions that work across languages.
- **If** a layout is built only for LTR text **then** RTL (Arabic, Hebrew) and vertical scripts break the layout and visual focus — **fix:** mirror the layout (including reversing key images/faces, as PayPal Israel does), set `dir="auto"` on mixed LTR/RTL elements (else bidi scrambles punctuation — Spotify "Let It Be"), and mirror directional icons (calendar, reply, nav arrows) but NOT non-directional ones (coffee cup) or video-player UI.
- **If** forms assume given-name-first, fixed name length, US postal codes, or one address order **then** real users worldwide are excluded — **fix:** support family-name-first, long/short/accented names, locale-aware address forms, prefilled regions.
- **If** dates, currency, tax/VAT, or exchange rates are shown in one Western format **then** users misread or abandon ("7/1/2011" is ambiguous; single-currency billing loses customers; inauspicious numbers like 4=death in Japan, 666) — **fix:** store dates in UTC and reformat per locale; let users set country/language/currency independently; show exchange rates + currency codes; disclose VAT before checkout.
- **If** color is chosen by a "color meanings" listicle **then** it hides the real gap — lack of local knowledge **because** meanings are arbitrary cultural lore (green=Islam in Indonesia vs. money in US; red=auspicious in China vs. danger in US) — **fix:** build palettes from local art/culture, validate with local collaborators, check against a color-blindness simulator.
- **If** a high-power-distance audience gets a flat "Home > All" taxonomy or an AI chatbot with no credentials **then** trust drops; a high-uncertainty-avoidance audience facing vague errors or dense dashboards gets anxious; a restraint-oriented audience meets humor/smiling-stranger stock — all mismatch cultural expectation — **fix:** match authority markers, taxonomy depth, error directness, redundancy, and tone to validated cultural research (use Hofstede as a hypothesis lens, not fact).
- **If** stock photos are smiling WEIRD-default strangers, or skin tones are wrong for the locale **then** the imagery alienates the actual audience — **fix:** use diverse libraries, swap localized header imagery per market, represent the target culture's skin tones/ethnicities.
- **If** personas are text-only or use Western-name/"I"-voice/solo-device/individual-goal defaults **then** team bias fills the gap and collectivist/shared-device users are designed out — **fix:** asset-frame, pair archetypes with intentional diverse imagery and a real participant case study, represent shared accounts/group achievements.
- **If** localization is machine-translation only **then** brand nuance is lost and bias/errors creep in (Google Translate forced doctor=male, nurse=female) — **fix:** prefer human translation reviewed for tone/idiom/detail; at minimum offer simplified translated HTML (not PDFs) + a localization toolkit.
- **If** the design was built entirely from the team's own experience with no field research in target markets **then** it encodes the team's culture as universal — **fix:** run an Assumption Breaker, validate with real users *in their own environment* in each key market (lab gets only ~70–80%); use focus groups → contextual interviews to avoid groupthink; keep an interpreter/local guide even for nominal "English speakers."
- **If** a global product ships translation-only with no local adaptation, or imposes an over-rigid central template, or fabricates testimonials in a trust-sensitive market **then** it feels foreign and loses local loyalty — **fix:** add culturally relevant touches on evidence (ING France's local sports team raised consideration), allow local variation, use real verifiable social proof.
- **If** maps/borders/territories show a single authoritative view **then** you offend audiences in disputed regions (Kashmir, Crimea, Golan Heights) — **fix:** research disputed territories; show contested regions explicitly.
- **If** Google Fonts / Google-API services are used **then** they silently fail to load in regions where Google is blocked (mainland China) — **fix:** provide a regional fallback (e.g. Justfont).

## Testing

- **If** you rely on automated accessibility tools alone **then** judgment-call failures slip through (legit empty alt, wrong replaced-header text, captions copied into alt, illogical heading order) **because** tools can't reason — **fix:** also test manually with a real screen reader / keyboard.
- **If** a research schedule crams many sessions/day or screens "English speakers" without an interpreter **then** quality drops and nuance is lost **because** exhausted moderators can't engage and "speaking English" varies — **fix:** prefer ~12 deeply-engaged sessions over 30 rushed; keep a same-culture interpreter/guide in-room.
- **If** a report is slides/percentages to people who didn't go to the field **then** cultural insight won't land — **fix:** immersive reporting (research expo, project room, stories, photos, video); ≤5 key implications.
